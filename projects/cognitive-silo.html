Cognitive Silo: A Self-Hosted AI Stack on One GPU

A private AI stack for the AMD Radeon PRO W7900 in my workstation (48 GB, ROCm). One docker compose up starts local LLMs, speech-to-text and text-to-speech, image and video generation and per-project memory, all behind a single OpenAI-compatible gateway that falls back to GPT-4o when the GPU is busy.

Architecture

Everything that speaks the OpenAI API goes through the gateway, so an editor plugin, a script or the chat UI uses the same endpoint and key, and never needs to know which model runs where.

Fitting it in 48 GB

The language models and video generation share one card, so the memory is budgeted rather than left to chance. Ollama keeps at most two models loaded and never unloads them on a timer (OLLAMA_MAX_LOADED_MODELS=2, OLLAMA_KEEP_ALIVE=-1), and an init container warms the two everyday models at startup.

ModelUseVRAM
DeepSeek-R1 32BReasoning and code; kept loaded~20 GB

Asking for a third model makes Ollama evict the least recently used one. If the GPU is saturated, the gateway sends the request to GPT-4o instead of making the caller wait.

Making it repeatable

  • One script from a fresh clone. setup.sh checks the prerequisites, asks for the API keys and writes them to an untracked .env, skips models that are already downloaded, builds the containers, pulls the Ollama models and checks that everything answers.
  • Setup jobs, not manual steps. Three containers download model weights, pull the Ollama models and prepare Speaches on first start, then exit. Weights stay on disk, so later restarts are quick.
  • Start order from health. 13 of the 17 containers have health checks, and services wait for what they depend on to be healthy. Most images ship without curl, so the checks use bash /dev/tcp or Python's urllib.
  • Data where it belongs. Model weights live in a ./models folder; PostgreSQL, Qdrant, Redis and the UIs keep their data in named volumes that survive docker compose down.
  • Usable from anywhere. Other machines reach the gateway over Tailscale; the repository includes a Continue.dev configuration for VS Code and prompt templates for coding, debugging, hardware and UI work.
